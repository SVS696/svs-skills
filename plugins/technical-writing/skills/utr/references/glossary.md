# Рабочий словарь редактора

Словарь помогает выбрать формулировку, когда слово допускает разные прочтения. В статьях со ссылкой на ГОСТ приведены краткий пересказ конкретного пункта и пример для аналитика. Остальные пояснения и примеры — редакторские. Сначала определите, какой смысл задал источник и какой стандарт применяется к документу. В обычной постановке сохраняйте принятые в проекте названия и силу требования. Если термин проекта расходится с обязательным термином применимого стандарта, покажите расхождение владельцу документа. [Области применения и оригиналы](sources.md)

## Обязанность, возможность и доказательство

| Слово или выражение | Когда оно точно | Пример или различие |
|---|---|---|
| должен | Участник обязан выполнить действие | «Сервис должен вернуть номер заявки». В текстовом документе по ГОСТ Р 2.105-2019, п. 5.2.2, это одна из форм обязательного требования. |
| следует | Сила формулировки зависит от документа | В документе по ГОСТ Р 2.105-2019, п. 5.2.2, «следует» выражает обязательное требование. В обычной переписке сверьте с источником, предложено действие или предписано. |
| обязан | Установлена обязанность конкретного участника | Сохраните указанного носителя обязанности. |
| вправе | Роли предоставлено право | «Владелец вправе отозвать заявку». Отзыв доброволен. |
| разрешено | Действие допустимо при заданном условии | Уточните роль и область разрешения, если они есть в источнике. |
| запрещено | Источник устанавливает запрет | Отсутствие кнопки само по себе запрета не доказывает. |
| рекомендуется | Указан предпочтительный вариант | Сохраните рекомендательный характер. |
| допускается | Предусмотрен допустимый вариант или отступление | В документе по ГОСТ Р 2.105-2019, п. 5.2.2, «допускается» указывает на допустимый вариант. В выражении «не допускается» тот же пункт задаёт запрет. При редактуре сохраните отрицание и условие. |
| может | Возможны право, техническая способность или вероятный исход | «Оператор вправе повторить» и «при повторе возможна ошибка» описывают разные ситуации. |
| поддерживает | Интерфейс или компонент обладает указанной возможностью | «Импорт поддерживает CSV». Для обязательства используйте форму, принятую в спецификации. |
| доступен | Открыт доступ или объект достижим | Уточните, идёт ли речь о правах либо доступности сервиса. |
| подтверждён | Названо проверяемое основание | «Получение подтвердил ответ сервера». |
| наблюдался | Событие зафиксировано при определённых условиях | Одиночное наблюдение не задаёт общее поведение. |
| ожидается | Назван прогноз или ожидаемый результат теста | Укажите, какой из двух смыслов используется. |
| предположительно | Объяснение остаётся гипотезой | Сохраните исходную степень уверенности. |
| неизвестен | Данных для вывода нет | «Время поступления неизвестно». Нуль означает другое значение. |

## Условие, количество и время

| Слово или выражение | Когда оно точно | Пример или различие |
|---|---|---|
| если | Действие зависит от условия | «Если запись закрыта, сервис отклоняет изменение». |
| когда | Результат привязан к событию | «Когда сервер подтверждает запись, клиент закрывает окно». |
| пока | Правило действует в течение состояния | «Пока идёт импорт, команда недоступна». |
| только если | Условие обязательно для результата | Само условие ещё не гарантирует результат. |
| только | Ограничивает следующий элемент | «Только владелец читает черновик» и «владелец только читает черновик» различаются. |
| кроме | Обозначает исключённый случай | Назовите множество, к которому относится исключение. |
| каждый | Правило относится ко всем элементам по отдельности | «У каждого файла есть собственный идентификатор». |
| хотя бы один | Достаточно одного элемента, больше допускается | Отличайте от «ровно один». |
| ровно один | Обязателен единственный элемент | Нуль и два элемента нарушают условие. |
| не менее | Нижняя граница включена | Не менее 3 — значения 3 и выше. |
| более | Нижняя граница исключена | Более 3 — значение 3 не подходит. |
| не более | Верхняя граница включена | Не более 5 попыток включает пятую. |
| менее | Верхняя граница исключена | Менее 5 с исключает ровно 5 с. |
| до | Может обозначать время либо числовой предел | Для «до 10» уточните, входит ли 10. Для срока уточните событие начала и часовой пояс, если они влияют на результат. |
| в течение | Задан интервал от известного события | «В течение 30 с после подтверждения». |
| не ранее | Время события ограничено снизу | Граничный момент включён. Сохраните точку отсчёта, если она задана. |
| последовательно | Следующее действие начинается после указанного предыдущего | Определите, требуется ли завершение или подтверждение предыдущего шага. |
| одновременно | Действия приходятся на одно время в смысле исходной операции | Объединение двух записей в транзакцию само по себе не устанавливает их одновременность. |
| атомарно | Изменения образуют одно целое для заявленной гарантии | «При сбое сохраняются обе записи или ни одна». |
| по умолчанию | Значение действует при отсутствии явно заданного выбора | Отсутствующее поле, пустая строка и `null` могут иметь разные значения. |

## Действие, состояние и результат

| Термин | Когда он точен | Что следует проверить |
|---|---|---|
| создать | Появляется новый объект | Создание объекта само по себе не задаёт способ присвоения идентификатора. |
| сохранить | Значение записано в указанное хранилище | Сохраните заданный момент записи или её подтверждения, если от него зависит действие. |
| обновить | Существующий объект получил новое значение | Как определяется объект и какое поле меняется. |
| заменить | Новое значение занимает место прежнего | Дополнение списка отличается от полной замены. |
| добавить | Состав множества или списка расширяется | Из «добавить» само по себе не следует, как обработать дубликат. |
| удалить | Объект или данные удаляются в смысле контракта | Удаление, скрытие и пометка об удалении требуют разных формулировок. |
| очистить | Содержимое удаляется, контейнер может сохраниться | Назовите, что именно остаётся после операции. |
| сбросить | Значение возвращается в определённое состояние | Укажите исходное, пустое или заданное по умолчанию значение по источнику. |
| отменить | Начатое или запланированное действие прекращается | Откат уже совершённых изменений требует отдельного основания. |
| отклонить | Запрос не принят по определённой причине | Код ответа или наблюдаемый результат, если он задан. |
| зарегистрировать | Ведущая система создаёт запись о событии или объекте | Регистрация заявки не означает её одобрения. |
| отправить | Запрос или сообщение переданы из точки отправки | Отправка не свидетельствует о записи у получателя. |
| получить | Получателю стали доступны данные или сообщение | Источник подтверждения на стороне получателя. |
| подтвердить | Участник или система засвидетельствовали точный факт | «Подтвердить получение» и «согласовать содержание» решают разные задачи. |
| согласовать | Ответственная сторона выразила согласие | Это может быть промежуточным этапом перед утверждением. |
| утвердить | Уполномоченный участник принял формальное решение | Сохраните предмет решения и полномочия, которые установил источник. |
| вернуть | Указанный отправитель формирует результат для вызывающей стороны | Назовите поле ответа или объект результата. |
| показать | Читатель увидит результат в интерфейсе | Отдельно укажите сохранение данных, если оно требуется. |
| сравнить | Установить соотношение двух значений | Укажите значения и правило сравнения. |
| сверить | Проверить соответствие конкретному образцу или источнику | Назовите эталон. |
| повторить | Запустить то же действие ещё раз | Сохраните заданные условия повтора. У операции может не быть ключа запроса. |
| восстановить | Вернуть данные или работу к указанному состоянию | Заданное состояние или результат восстановления. Способ восстановления определяется отдельно. |
| завершён | Процесс достиг конечного состояния | Завершение с ошибкой и успешное завершение различайте по источнику. |
| принят | Возможны получение запроса, одобрение или формальная приёмка | Выберите значение по роли, документу или наблюдаемому переходу. |
| идентификатор | Устойчивое обозначение конкретного объекта в заданной области | Человекочитаемое имя может совпадать у разных объектов. Для требования по ГОСТ Р 59194-2020, п. 6.2.2, идентификатор сохраняется при изменении текста требования. Правило относится к идентификатору требования. |
| событие | Факт, произошедший в определённый момент | Условие «сохранение завершилось» отлично от состояния «документ сохранён». |
| статус | Значение именованного атрибута модели | Если контракт использует `PENDING`, сохраните литерал с учётом регистра. |
| версия | Определённая редакция данных или документа | Для требований по ГОСТ Р 59194-2020, пп. 3.1.6 и 6.2.2, версия фиксирует содержание вместе с атрибутами. При изменении требования создают его новую версию. Для поля API значение слова задаёт контракт. |
| запись | Значение зависит от предмета документа | В п. 3.9 ГОСТ Р 58049-2017 «запись» обозначает документ, в котором зафиксирован результат или свидетельство выполненной работы. В API слово может обозначать объект данных, а в выражении «повторить запись» — действие. Выберите смысл по исходной операции. |
| техническое задание (ТЗ) | Сначала определите предмет задания | Для перевода по ГОСТ Р 58049-2017, п. 3.35, стороны письменно согласуют требования к тексту перевода и его оформлению. Для автоматизированной системы по ГОСТ 34.602-2020, п. 3.1, ТЗ задаёт требования к системе и порядок её создания, служит основанием для разработки и приёмки. Одного названия «ТЗ» недостаточно, чтобы выбрать форму документа. |

## Что именно проверяют

В ГОСТ Р 59194-2020 различаются четыре предмета проверки. В постановке сохраняйте то, для чего есть свидетельство. Например, рецензент может проверить критерий приёмки до появления работающей функции.

| Термин | Смысл в ГОСТ Р 59194-2020 | Пример для аналитика |
|---|---|---|
| Верификация требований | Пункт 3.1.5. Содержание и оформление требований проверяют по заданным критериям качества. | Рецензент проверил, однозначно ли критерий задаёт границу срока. |
| Валидация требований | Пункт 3.1.3. Проверяют, позволит ли выполнение требований удовлетворить потребности заинтересованных сторон. | По сценарию сверили с диспетчером, решит ли предусмотренное уведомление его задачу. |
| Верификация объекта | Пункт 3.1.4. Свидетельства подтверждают соответствие объекта заданным требованиям. | На стенде измерили задержку уведомления и сравнили её с пределом из требования. |
| Валидация объекта | Пункт 3.1.2. Свидетельства подтверждают, что объект отвечает потребностям заинтересованных сторон. | Диспетчер успел отреагировать на уведомление в рабочем сценарии. |

## Тяжёлые обороты

| Исходное выражение | Удобная форма при известном смысле | Когда остановиться |
|---|---|---|
| осуществить проверку | проверить | Сохраните официальное название процедуры, если оно определяет отдельный этап. |
| произвести настройку | настроить | Укажите объект и требуемое значение, если они заданы. |
| по завершении процесса загрузки | после завершения загрузки | Выясните, идёт ли речь о передаче файла или о его обработке. |
| при наличии необходимости | если выполнено условие | Не придумывайте условие или срок. |
| в целях обеспечения возможности | чтобы участник мог выполнить действие | При установленном праве используйте «вправе». |
| соответствующий | названный объект или точная ссылка | Если подходят два объекта, уточните ссылку. |
| данный, вышеуказанный | существительное или короткое утверждённое обозначение | Уберите слово, только если объект однозначен. |
| корректный, надлежащий | проверяемое свойство | Уточните критерий, если без него возможны разные результаты. |
| своевременно, оперативно | срок с точкой отсчёта | Не добавляйте численное обещание. |
| обработать | конкретное действие и наблюдаемый результат | Если «обработка» — имя контрактной операции, сохраните его и определение. |
| и/или | одно из условий или оба | Если выражение допускает несколько прочтений, проверьте случай, когда выполнены оба условия. Для «ровно одно» нужно основание в источнике. |
| успешно | наблюдаемый признак успеха | Если признак определён статусом, укажите точный статус. |

## Как завести термин проекта

Для перевода эксплуатационной документации ГОСТ Р 58049-2017 различает **терминологическую базу** (п. 3.34) и **глоссарий** (п. 3.8). База связывает предметные термины с утверждёнными вариантами перевода. Глоссарий может охватывать также общую лексику, имена и сокращения, нужные для перевода. Порядок работы с ними описан в пп. 8.1.3–8.1.8. [Правила по терминологии](rules.md)

Если задача включает ведение словаря, запишите понятие, его значение и принятую форму. Добавьте область употребления, литерал, перевод, конкурирующие обозначения и источник решения там, где эти сведения помогают выбрать термин. Для согласуемого словаря укажите статус и того, кто его утвердил. При совпадении формы у разных понятий сделайте отдельные записи.

| Понятие | Форма и значение | Ограничение и источник |
|---|---|---|
| Состояние задания | Ожидает запуска — задание принято в очередь | Учебный контракт. В данных хранится `QUEUED`. Для пользовательского сообщения подходит русская форма, в фильтре API нужен точный литерал. |
| Роль в договоре | Владелец заявки — участник, которому принадлежит заявка | Учебный договор. Автор и владелец могут различаться. При переносе в иной проект надо проверить определение. |
