# Правила УТР для автора и редактора

Раздел 8 ГОСТ Р 58049-2017 описывает письменный перевод эксплуатационной документации (ЭД) авиационной техники. В этом справочнике номера обозначают пункты стандарта. Рядом даны редакторские вопросы и собственные примеры. Для формального заключения обратитесь к полному тексту. Для постановки или API также примените [правила соответствующего жанра](extensions.md). [Издание и область применения](sources.md)

## Область и терминология

| Пункт | Что проверить |
|---|---|
| 8.1.1 | Для перевода ЭД с русского и на русский стандарт рекомендует УТР. Установите язык оригинала, язык перевода и требования заказчика. |
| 8.1.2, 8.1.2.1, 8.1.2.2 | Перевод на русский должен быть однозначным и терминологически последовательным. Подготовка русского оригинала облегчает последующий перевод. Уточните, есть ли у целевого языка свой контролируемый профиль. Учитывайте объём, трудоёмкость редактуры и риск искажения в обоих направлениях. |
| 8.1.3–8.1.5 | Для внедрения УТР в переводческий проект нужна двунаправленная база терминов. Лексикограф исполнителя или сторона заказчика составляет и обновляет её. Заказчик и поставщик переводческих услуг утверждают её до начала перевода. Включайте принятые предметные термины и сочетания. Сверяйте их с ограничениями целевого языка. |
| 8.1.6 | Используйте согласованную терминологическую базу в применяемой системе автоматизированного перевода. |
| 8.1.7, 8.1.8 | Для общей лексики, имён, сокращений и вариантов перевода можно вести отдельный электронный глоссарий. За его составление отвечает лексикограф заказчика или исполнителя. Стороны согласуют его до начала работ. Учитывайте ограничения целевого языка при обновлении глоссария. |
| 8.1.9, 8.1.10 | Устраняйте разнобой в названиях и лишние пояснения. Если термин для перевода ЭД установлен применимым национальным стандартом, используйте это значение. При необходимости зафиксируйте источник терминологии в материалах заказа. |
| 8.2.1 | При переводе на иностранный язык можно сначала отредактировать русский текст. После этого исходником перевода служит согласованная редакция. Сохраните её версию. |
| 8.2.2, 8.2.2.1 | Для иностранного результата действуют грамматика и лексика целевого языка. Если заказан контролируемый язык, дополнительно примените его правила словоупотребления. |

При обычной редактуре на одном языке отметьте термины, для которых у проекта пока нет определения. Используйте рабочий словарь в пределах его значений. Согласование полноценного переводческого проекта требуется только там, где такой процесс действительно применяется.

## Как строить фразу в ЭД

| Пункт | Приём и способ проверки |
|---|---|
| 8.2.3.1, 8.2.3.2 | Попросите читателя назвать объект и действие. Если допустимы два объекта или два действия с разным исходом, уточните связь по источнику. |
| 8.2.3.3 | Выберите форму по задаче. Действительный залог подходит для известного исполнителя. Безличная или неопределённо-личная конструкция уместна, когда исполнитель несущественен. Команду читателю дайте во множественном числе. |
| 8.2.3.4 | Используйте прямой порядок. В простом предложении ставьте подлежащее перед сказуемым, прямое дополнение после сказуемого. Пример — «Датчик передаёт давление». |
| 8.2.3.5 | Метафоры, сравнения и профессиональный жаргон замените точным действием. Для фразы «очередь захлебнулась» выясните, что наблюдалось: полная очередь, тайм-аут или потеря сообщений. |
| 8.2.3.6 | При равнозначных русских терминах используйте русское обозначение. В издании 2017 года дана датированная ссылка на п. 4.2 ГОСТ 2.105-95. При проверке другого договора уточните требуемую редакцию ЕСКД. Оригинальное имя поля или иностранную надпись прибора передайте точно. |
| 8.2.3.7, 8.2.3.8 | Проверьте, принят ли термин в предметной области. Выберите простое короткое обозначение, если оно сохраняет значение. Предложенное сокращение внесите в глоссарий для утверждения. |
| 8.2.3.9 | В операции настройки, сборки или диагностики поставьте глагол в начало команды. Обращайтесь к читателю во множественном числе. Пример — «Сверьте номер партии с записью в журнале». |
| 8.2.3.10 | Проверьте цепочки из трёх и более существительных. Раскройте, кто чем управляет и к чему относится определение. Для неизменяемого длинного термина дайте пояснение и сокращённое обозначение, затем используйте его. |
| 8.2.3.11 | Разберите причастные и деепричастные обороты, громоздкие сказуемые. Разделите фразу, если при этом сохраняются субъект и время. «Проверив запись, окно закрылось» не указывает, кто проверял запись. |
| 8.2.3.12, 8.2.3.14 | По возможности дайте отдельным действиям отдельные предложения. Если последовательность приходится сохранить в сложной фразе, явно свяжите действия союзом. |
| 8.2.3.13 | Избегайте пассива при описании инструкции. Если источник не позволяет установить ответственного, оставьте неопределённость видимой. |
| 8.2.3.15 | После сокращения проверьте условия, объекты и единицы. «Повторите для правой секции» теряет смысл, если исходный шаг применялся только к закрытой правой секции. |
| 8.2.3.16 | В сложном тексте разверните перечисление в вертикальный список. Одно основание должно относиться ко всем его пунктам. Если важен порядок, укажите последовательность. |
| 8.2.3.17 | Скобки подходят для ссылки на рисунок или текст, обозначения позиции, пояснения, сложного обособления и вложенного пункта инструкции. Вынесите из скобок условие, которое читателю требуется увидеть до действия. |
| 8.2.3.18 | ЭД рекомендует убирать избыточные названия элементов интерфейса. Пример — «Выберите „История“». Если одноимённые вкладка и команда ведут к разным результатам, укажите вид элемента. |
| 8.2.3.19 | Оставьте в примечании дополнительные сведения. Запрет или предварительное условие перенесите к действию. |

## Как редактировать перевод

| Пункт | Вопрос к редакции |
|---|---|
| 8.2.4.1 | Сохранены ли исходные утверждения и их связи? Исключите добавленные обязанности, диагнозы и обещания результата. |
| 8.2.4.2, 8.2.4.3 | Сохранились ли функция документа и регистр языка? В журнале оставьте наблюдение, в руководстве — обращение к оператору. |
| 8.2.4.4 | Соответствуют ли грамматика и термины жанру? Проверьте согласование терминов с ранее переведёнными частями. |
| 8.2.4.5 | По какому признаку выбран смысл многозначного слова? Для английского `record` сначала определите, имеется ли в виду запись данных или действие регистрации. |
| 8.2.4.6 | Для перевода с пересчётом величин используйте систему мер страны назначения. В скобках сохраните исходное значение вместе с единицей. Проверьте точность пересчёта. В техническом контракте без задачи перевода единиц сохраните размерность и значение источника. |

## Инструкция, описание и предупреждение

| Пункт | Что сделать |
|---|---|
| 8.2.5.1 | Для инструкции ориентируйтесь максимум на 20 слов в предложении. Это рекомендация. При превышении найдите место для деления и проверьте смысл обеих частей. |
| 8.2.5.2 | Отведите предложение одной команде. Несколько команд в одном предложении допустимы для одновременных действий. Отмечайте одновременность прямо. |
| 8.2.5.3, 8.2.5.4 | Дайте конкретную команду во множественном числе. Читатель должен найти нужный объект и понять, какое действие требуется. |
| 8.2.6.1, 8.2.6.2 | Для описания также рекомендован предел в 20 слов. В каждом абзаце раскройте одну тему. Сведения о причине сохраните рядом с тем состоянием, которое она объясняет. |
| 8.2.7 | Начните предупреждение с понятной команды. Если перед началом работ нужно распознать условие, сначала назовите его. Когда нужно объяснить риск, дайте краткое последствие, подтверждённое источником. Пример — «Если импорт уже запущен, дождитесь его окончания. Повторный запуск перезапишет текущий файл». |

Для программного скилла с обращением к одному агенту проект может принять другую форму команды. Укажите это как проектное решение, если нужна проверка по п. 8.2.5.3. Точное имя команды и программный идентификатор сохраняйте при любом обращении.
